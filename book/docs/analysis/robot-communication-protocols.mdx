# Robot Communication Protocols

## Introduction

Robotic systems rely on various communication protocols to coordinate between different components. This document provides an overview of the most common protocols used in robotics, with a focus on Robot Operating System (ROS) and its communication mechanisms.

## ROS Communication Primitives

### Topics

Topics provide asynchronous, many-to-many communication using a publish-subscribe model.

```python
# Publisher
publisher = rospy.Publisher('/cmd_vel', Twist, queue_size=10)

# Subscriber
def callback(msg):
    # Process received message
    pass

subscriber = rospy.Subscriber('/sensor_data', SensorData, callback)
```

**Use cases:**
- Continuous sensor data streams
- Robot control commands
- Status updates

### Services

Services provide synchronous, request-response communication.

```python
# Service server
def handle_request(req):
    # Process request and return response
    return ServiceResponse(result=True)

service = rospy.Service('/get_plan', GetPlan, handle_request)

# Service client
client = rospy.ServiceProxy('/get_plan', GetPlan)
response = client(request_params)
```

**Use cases:**
- Discrete operations
- Querying information
- Operations with immediate results

### Actions

Actions provide asynchronous communication with feedback and goal management.

```python
# Action client
client = actionlib.SimpleActionClient('/move_base', MoveBaseAction)
client.wait_for_server()

goal = MoveBaseGoal(target_pose)
client.send_goal(goal, done_cb=done_callback, feedback_cb=feedback_callback)

# Action server
class MoveBaseActionServer:
    def __init__(self):
        self.server = actionlib.SimpleActionServer(
            '/move_base',
            MoveBaseAction,
            execute_cb=self.execute,
            auto_start=False
        )
        self.server.start()
```

**Use cases:**
- Long-running operations
- Operations requiring feedback
- Operations with multiple outcomes

## Protocol Selection Guidelines

### When to Use Each Protocol

| Scenario | Recommended Protocol | Rationale |
|----------|---------------------|-----------|
| Continuous sensor data | Topics | High-frequency, asynchronous updates |
| Robot control commands | Topics | Low-latency, continuous control |
| Requesting a specific plan | Services | Synchronous, discrete operation |
| Navigation to a goal | Actions | Long-running with feedback |
| Object manipulation | Actions | May require feedback and has multiple states |

### Performance Considerations

- **Topics**: Best for high-frequency data, but can overwhelm network if not properly managed
- **Services**: Good for discrete operations, but can block if server is unavailable
- **Actions**: Best for complex operations, but more overhead than topics/services

## Advanced Communication Patterns

### ActionLib for Complex Tasks

```python
import actionlib
import rospy

class ComplexTaskServer:
    def __init__(self):
        self.server = actionlib.SimpleActionServer(
            'complex_task',
            ComplexTaskAction,
            execute_cb=self.execute_complex_task,
            auto_start=False
        )
        self.server.start()

    def execute_complex_task(self, goal):
        result = ComplexTaskResult()
        feedback = ComplexTaskFeedback()

        try:
            # Break down complex task into steps
            for i, subtask in enumerate(goal.subtasks):
                success = self.execute_subtask(subtask)

                if not success:
                    result.success = False
                    result.error_code = f"Subtask {i} failed"
                    self.server.set_aborted(result)
                    return

                # Provide feedback
                feedback.completed_tasks = i + 1
                feedback.total_tasks = len(goal.subtasks)
                self.server.publish_feedback(feedback)

            result.success = True
            self.server.set_succeeded(result)

        except Exception as e:
            result.success = False
            result.error_code = str(e)
            self.server.set_aborted(result)
```

### Coordination with Action Servers

```python
class TaskCoordinator:
    def __init__(self):
        # Multiple action clients for different capabilities
        self.nav_client = actionlib.SimpleActionClient('move_base', MoveBaseAction)
        self.manip_client = actionlib.SimpleActionClient('manipulation', ManipulationAction)
        self.perception_client = actionlib.SimpleActionClient('object_detection', ObjectDetectionAction)

    def execute_complex_task(self, task_plan):
        """Execute a multi-step task using different action servers"""
        for step in task_plan:
            if step.type == 'navigation':
                self.nav_client.send_goal(step.goal)
                self.nav_client.wait_for_result()
            elif step.type == 'manipulation':
                self.manip_client.send_goal(step.goal)
                self.manip_client.wait_for_result()
            elif step.type == 'perception':
                self.perception_client.send_goal(step.goal)
                self.perception_client.wait_for_result()
```

## Best Practices

### 1. Protocol Selection

- Choose the right protocol for your use case
- Consider timing requirements
- Think about error handling needs

### 2. Message Design

- Keep messages focused and efficient
- Include appropriate metadata (timestamps, frame IDs)
- Design for extensibility

### 3. Error Handling

- Implement timeouts for services
- Use feedback in actions to detect progress
- Design graceful degradation strategies

### 4. Network Considerations

- Consider bandwidth when choosing protocols
- Use compression for large data
- Implement reconnection logic for unreliable networks
