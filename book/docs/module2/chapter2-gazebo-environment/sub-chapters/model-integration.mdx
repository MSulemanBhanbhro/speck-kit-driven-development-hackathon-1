# Model Integration and Testing

Proper integration and testing of robot models in Gazebo is crucial for successful simulation. This chapter covers the essential techniques for importing, configuring, and validating robot models in the Gazebo environment, with a focus on humanoid robotics applications.

## Model Import and Conversion

### URDF to SDF Conversion

Gazebo primarily uses SDF (Simulation Description Format), but most robot models are created in URDF (Unified Robot Description Format). The conversion process requires careful attention to details:

```xml
<!-- Example of URDF to SDF integration in Gazebo -->
<model name="my_robot">
  <static>false</static>
  <link name="base_link">
    <inertial>
      <mass>1.0</mass>
      <inertia>
        <ixx>0.01</ixx>
        <ixy>0.0</ixy>
        <ixz>0.0</ixz>
        <iyy>0.01</iyy>
        <iyz>0.0</iyz>
        <izz>0.01</izz>
      </inertia>
    </inertial>

    <collision name="collision">
      <geometry>
        <box><size>0.5 0.5 0.2</size></box>
      </geometry>
    </collision>

    <visual name="visual">
      <geometry>
        <mesh><uri>model://my_robot/meshes/base_link.dae</uri></mesh>
      </geometry>
      <material>
        <script>
          <uri>file://media/materials/scripts/gazebo.material</uri>
          <name>Gazebo/Blue</name>
        </script>
      </material>
    </visual>
  </link>
</model>
```

### Model Directory Structure

Organize your robot models following Gazebo's expected structure:

```
~/.gazebo/models/my_robot/
├── model.config          # Model metadata and description
├── model.sdf             # SDF description (or URDF)
├── meshes/               # 3D mesh files
│   ├── base_link.dae
│   ├── link1.dae
│   └── ...
├── materials/            # Material definitions
│   └── textures/         # Texture images
└── scripts/              # Custom scripts and plugins
```

Example `model.config` file:
```xml
<?xml version="1.0"?>
<model>
  <name>My Robot</name>
  <version>1.0</version>
  <sdf version="1.7">model.sdf</sdf>
  <author>
    <name>Your Name</name>
    <email>your.email@example.com</email>
  </author>
  <description>A humanoid robot model for Gazebo simulation.</description>
</model>
```

## Joint and Actuator Configuration

### Joint Types and Properties

Configure different joint types appropriately for humanoid robots:

```xml
<!-- Revolute joint (rotational) -->
<joint name="hip_joint" type="revolute">
  <parent>base_link</parent>
  <child>thigh_link</child>
  <axis>
    <xyz>0 0 1</xyz>
    <limit>
      <lower>-1.57</lower>
      <upper>1.57</upper>
      <effort>100.0</effort>
      <velocity>3.0</velocity>
    </limit>
    <dynamics>
      <damping>1.0</damping>
      <friction>0.1</friction>
    </dynamics>
  </axis>
  <pose>0.1 0 0 0 0 0</pose>
</joint>

<!-- Continuous joint (unlimited rotation) -->
<joint name="head_pan_joint" type="continuous">
  <parent>neck_link</parent>
  <child>head_link</child>
  <axis>
    <xyz>0 0 1</xyz>
    <dynamics>
      <damping>0.5</damping>
    </dynamics>
  </axis>
</joint>

<!-- Fixed joint (no movement) -->
<joint name="sensor_joint" type="fixed">
  <parent>head_link</parent>
  <child>camera_link</child>
  <pose>0.05 0 0.1 0 0 0</pose>
</joint>
```

### Actuator Models

Configure actuators with realistic parameters:

```xml
<!-- Motor joint for actuator simulation -->
<joint name="motor_joint" type="revolute">
  <parent>upper_arm</parent>
  <child>lower_arm</child>
  <axis>
    <xyz>0 1 0</xyz>
    <limit>
      <lower>-2.0</lower>
      <upper>2.0</upper>
      <effort>50.0</effort>
      <velocity>2.0</velocity>
    </limit>
  </axis>
</joint>

<!-- Gazebo-specific actuator plugin -->
<gazebo reference="motor_joint">
  <provideFeedback>true</provideFeedback>
  <implicitSpringDamper>true</implicitSpringDamper>
  <joint>
    <type>revolute</type>
    <axis>
      <xyz>0 1 0</xyz>
      <limit>
        <lower>-2.0</lower>
        <upper>2.0</upper>
        <effort>50.0</effort>
        <velocity>2.0</velocity>
      </limit>
    </axis>
  </joint>
</gazebo>
```

## Sensor Integration

### Camera Sensors

Configure camera sensors for humanoid robot perception:

```xml
<gazebo reference="camera_link">
  <sensor name="rgb_camera" type="camera">
    <update_rate>30.0</update_rate>
    <camera name="head_camera">
      <horizontal_fov>1.047</horizontal_fov>  <!-- 60 degrees -->
      <image>
        <width>640</width>
        <height>480</height>
        <format>R8G8B8</format>
      </image>
      <clip>
        <near>0.1</near>
        <far>10.0</far>
      </clip>
      <noise>
        <type>gaussian</type>
        <mean>0.0</mean>
        <stddev>0.007</stddev>
      </noise>
    </camera>
    <plugin name="camera_controller" filename="libgazebo_ros_camera.so">
      <frame_name>camera_optical_frame</frame_name>
      <min_depth>0.1</min_depth>
      <max_depth>10.0</max_depth>
      <camera_name>head_camera</camera_name>
      <image_topic_name>image_raw</image_topic_name>
      <camera_info_topic_name>camera_info</camera_info_topic_name>
    </plugin>
  </sensor>
</gazebo>
```

### Force/Torque Sensors

Configure force/torque sensors for manipulation:

```xml
<gazebo reference="wrist_joint">
  <sensor name="ft_sensor" type="force_torque">
    <always_on>true</always_on>
    <update_rate>100</update_rate>
    <force_torque>
      <frame>sensor_local</frame>
      <measure_direction>child_to_parent</measure_direction>
    </force_torque>
    <plugin name="ft_sensor_controller" filename="libgazebo_ros_ft_sensor.so">
      <topicName>wrist/ft_sensor</topicName>
      <jointName>wrist_joint</jointName>
    </plugin>
  </sensor>
</gazebo>
```

## Model Testing and Validation

### Static Model Testing

Test model configuration without physics:

```xml
<!-- Test with static model first -->
<model name="test_model">
  <static>true</static>  <!-- Disable physics for initial testing -->
  <link name="base_link">
    <!-- Model definition -->
  </link>
</model>
```

### Physics Validation

Once static testing passes, enable physics and validate:

```xml
<!-- Enable physics with proper parameters -->
<model name="robot_model">
  <static>false</static>
  <link name="base_link">
    <inertial>
      <!-- Proper mass and inertia values -->
      <mass>10.0</mass>
      <inertia>
        <ixx>0.1</ixx>
        <ixy>0.0</ixy>
        <ixz>0.0</ixz>
        <iyy>0.1</iyy>
        <iyz>0.0</iyz>
        <izz>0.1</izz>
      </inertia>
    </inertial>
  </link>
</model>
```

### Joint Limits and Safety

Validate joint limits and safety constraints:

```xml
<!-- Test joint limits -->
<gazebo reference="joint_name">
  <joint>
    <axis>
      <limit>
        <lower>-1.57</lower>  <!-- Ensure limits are appropriate -->
        <upper>1.57</upper>
        <effort>50.0</effort>
        <velocity>2.0</velocity>
      </limit>
    </axis>
  </joint>
</gazebo>
```

## Controller Integration

### ROS Control Integration

Integrate with ROS control for actuator commands:

```xml
<!-- Transmission for ROS control -->
<transmission name="tran1">
  <type>transmission_interface/SimpleTransmission</type>
  <joint name="motor_joint">
    <hardwareInterface>hardware_interface/PositionJointInterface</hardwareInterface>
  </joint>
  <actuator name="motor">
    <hardwareInterface>hardware_interface/PositionJointInterface</hardwareInterface>
    <mechanicalReduction>1</mechanicalReduction>
  </actuator>
</transmission>

<!-- Gazebo ROS control plugin -->
<gazebo>
  <plugin name="gazebo_ros_control" filename="libgazebo_ros_control.so">
    <robotNamespace>/my_robot</robotNamespace>
    <robotSimType>gazebo_ros_control/DefaultRobotHWSim</robotSimType>
  </plugin>
</gazebo>
```

### PID Controller Configuration

Configure PID controllers for precise actuator control:

```xml
<!-- Control configuration (typically in separate YAML file) -->

      p: 100.0
      i: 0.01
      d: 10.0

      p: 200.0
      i: 0.02
      d: 20.0
```

## Debugging and Troubleshooting

### Common Issues and Solutions

1. **Model falls through ground**:
   - Check mass and inertia values
   - Verify collision geometry
   - Adjust physics parameters

2. **Jittery motion**:
   - Reduce time step size
   - Increase solver iterations
   - Adjust constraint parameters

3. **Joint limits not working**:
   - Verify joint type and limits in SDF
   - Check for conflicting plugins
   - Validate URDF to SDF conversion

### Diagnostic Tools

Use Gazebo's diagnostic tools for model validation:

```bash
# Launch with verbose output
gzserver --verbose world_file.world

# Check model state
rostopic echo /gazebo/model_states

# Monitor physics performance
rostopic echo /gazebo/link_states
```

## Performance Optimization

### Model Simplification

Optimize models for better performance:

```xml
<!-- Use simplified collision geometry -->
<link name="visual_link">
  <collision name="collision">
    <!-- Simple shape instead of complex mesh -->
    <geometry>
      <cylinder>
        <radius>0.1</radius>
        <length>0.5</length>
      </cylinder>
    </geometry>
  </collision>
  <visual name="visual">
    <!-- Detailed visual mesh -->
    <geometry>
      <mesh><uri>meshes/detailed_model.dae</uri></mesh>
    </geometry>
  </visual>
</link>
```

### Level of Detail (LOD)

Implement LOD for complex models:

```xml
<!-- Multiple detail levels -->
<model name="detailed_robot">
  <!-- High detail version -->
  <link name="high_detail">
    <visual name="visual">
      <geometry>
        <mesh><uri>meshes/high_detail.dae</uri></mesh>
      </geometry>
    </visual>
  </link>

  <!-- Low detail version for distant viewing -->
  <link name="low_detail">
    <visual name="visual">
      <geometry>
        <mesh><uri>meshes/low_detail.dae</uri></mesh>
      </geometry>
    </visual>
  </link>
</model>
```

## Best Practices

### Model Standards

1. **Consistent Units**: Use consistent units throughout (typically meters, kilograms, seconds)
2. **Realistic Inertias**: Calculate mass and inertia based on actual dimensions and materials
3. **Proper Scaling**: Ensure model dimensions match real robot
4. **Documentation**: Document all parameters and assumptions

### Testing Strategy

1. **Incremental Testing**: Test components individually before full integration
2. **Physics Validation**: Verify physical behavior matches expectations
3. **Sensor Validation**: Test sensor outputs in various conditions
4. **Controller Testing**: Validate control responses and stability

Model integration and testing is a critical step in creating effective simulation environments. Properly configured models ensure realistic simulation behavior and reliable transfer of results to real-world applications.
