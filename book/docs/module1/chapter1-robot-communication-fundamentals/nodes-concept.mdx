# Understanding ROS 2 Nodes

## What is a Node?

A node in ROS 2 is the fundamental unit of computation that performs specific tasks and communicates with other nodes through the ROS 2 communication infrastructure. Think of a node as a single process that encapsulates a specific functionality within a robotic system. Each node runs independently and can interact with other nodes through topics, services, or actions.

According to the ROS 2 documentation, nodes are designed to be modular and reusable components that can be combined to create complex robotic behaviors (ROS.org, 2023). This modular approach allows developers to build sophisticated systems by combining simple, well-defined components.

## Node Architecture and Structure

### Basic Node Components

Every ROS 2 node consists of several key components:

1. **Node Name**: A unique identifier within the ROS 2 graph that allows other nodes to identify and communicate with it
2. **Node Handle**: The interface through which the node interacts with the ROS 2 middleware
3. **Communication Interfaces**: Publishers, subscribers, service servers, and clients that enable the node to communicate
4. **Execution Context**: The environment in which the node's callbacks are executed

### Node Lifecycle

ROS 2 nodes follow a well-defined lifecycle that includes:

- **Unconfigured State**: The node is created but not yet configured
- **Inactive State**: The node is configured but not yet active
- **Active State**: The node is running and processing data
- **Finalized State**: The node is shut down and cleaned up

This lifecycle management allows for more sophisticated control over node behavior and resource management (Macenski, S. (2021). *Professional Robotics: Tools and Applications for Robot Development*. Apress).

## Creating a Basic Node

### Python Implementation

In Python, nodes are created by inheriting from the `rclpy.Node` class. Here's a basic example:

```python
import rclpy
from rclpy.node import Node

class MinimalNode(Node):
    def __init__(self):
        super().__init__('minimal_node')
        self.get_logger().info('Minimal node created')
```

This simple node demonstrates the basic structure: a class that inherits from `Node`, a constructor that calls the parent constructor with a node name, and basic logging functionality.

### C++ Implementation

In C++, nodes are created by inheriting from the `rclcpp::Node` class:

```cpp
#include "rclcpp/rclcpp.hpp"

class MinimalNode : public rclcpp::Node
{
public:
    MinimalNode() : Node("minimal_node")
    {
        RCLCPP_INFO(this->get_logger(), "Minimal node created");
    }
};
```

## Node Communication Interfaces

### Publishers

Publishers allow nodes to send messages to topics. A node can have multiple publishers, each publishing to different topics:

```python
from std_msgs.msg import String

class PublisherNode(Node):
    def __init__(self):
        super().__init__('publisher_node')
        self.publisher = self.create_publisher(String, 'topic_name', 10)
        self.timer = self.create_timer(0.5, self.timer_callback)

    def timer_callback(self):
        msg = String()
        msg.data = 'Hello from publisher'
        self.publisher.publish(msg)
```

### Subscribers

Subscribers allow nodes to receive messages from topics:

```python
from std_msgs.msg import String

class SubscriberNode(Node):
    def __init__(self):
        super().__init__('subscriber_node')
        self.subscription = self.create_subscription(
            String,
            'topic_name',
            self.listener_callback,
            10)
        self.subscription  # prevent unused variable warning

    def listener_callback(self, msg):
        self.get_logger().info(f'I heard: {msg.data}')
```

### Service Servers

Service servers provide synchronous request-response communication:

```python
from example_interfaces.srv import AddTwoInts

class ServiceServerNode(Node):
    def __init__(self):
        super().__init__('service_server_node')
        self.srv = self.create_service(AddTwoInts, 'add_two_ints', self.add_two_ints_callback)

    def add_two_ints_callback(self, request, response):
        response.sum = request.a + request.b
        self.get_logger().info(f'Returning {response.sum}')
        return response
```

### Service Clients

Service clients call service servers:

```python
from example_interfaces.srv import AddTwoInts

class ServiceClientNode(Node):
    def __init__(self):
        super().__init__('service_client_node')
        self.cli = self.create_client(AddTwoInts, 'add_two_ints')
        while not self.cli.wait_for_service(timeout_sec=1.0):
            self.get_logger().info('Service not available, waiting again...')
        self.req = AddTwoInts.Request()

    def send_request(self, a, b):
        self.req.a = a
        self.req.b = b
        self.future = self.cli.call_async(self.req)
```

## Node Execution and Spinning

Nodes must be "spun" to process incoming messages and execute callbacks. The spinning mechanism handles the execution of callbacks for published messages, service requests, and action goals.

```python
def main(args=None):
    rclpy.init(args=args)
    node = MinimalNode()

    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()
```

## Best Practices for Node Development

### Naming Conventions

Node names should be descriptive and follow ROS 2 naming conventions:
- Use lowercase letters
- Separate words with underscores
- Be specific enough to identify the node's purpose

### Error Handling

Robust nodes should include proper error handling:

```python
class RobustNode(Node):
    def __init__(self):
        super().__init__('robust_node')
        try:
            # Initialize node components
            self.setup_components()
        except Exception as e:
            self.get_logger().error(f'Failed to initialize node: {e}')
            raise
```

### Resource Management

Nodes should properly manage resources and clean up when destroyed:

```python
def destroy_node(self):
    # Clean up resources
    if hasattr(self, 'timer'):
        self.timer.cancel()
    # Additional cleanup code
    super().destroy_node()
```

## Advanced Node Features

### Parameters

Nodes can accept parameters that can be configured at runtime:

```python
class ParameterNode(Node):
    def __init__(self):
        super().__init__('parameter_node')
        self.declare_parameter('param_name', 'default_value')
        param_value = self.get_parameter('param_name').value
```

### Timers

Timers allow nodes to execute callbacks at regular intervals:

```python
class TimerNode(Node):
    def __init__(self):
        super().__init__('timer_node')
        self.timer = self.create_timer(1.0, self.timer_callback)  # 1 second interval
```
