# Robot Structure Description

## Introduction to Robot Description

Robot description is a fundamental aspect of robotics that defines the physical structure of a robot, including its links (rigid bodies), joints (connections between links), and other properties such as visual and collision representations. In ROS 2, robot structure is typically described using the Unified Robot Description Format (URDF) or its more advanced variant, XACRO (XML Macros). These descriptions are essential for simulation, visualization, motion planning, and control of robotic systems.

According to the ROS documentation, URDF provides a way to represent a robot model as a tree structure of links and joints, which is crucial for tasks such as forward and inverse kinematics, collision detection, and robot simulation (ROS.org, 2023). For humanoid robots, accurate structure description is particularly important due to their complex kinematic chains and multiple degrees of freedom.

## Unified Robot Description Format (URDF)

### URDF Fundamentals

URDF (Unified Robot Description Format) is an XML-based format that describes robot models. A URDF file contains:

1. **Links**: Rigid bodies that make up the robot structure
2. **Joints**: Connections between links that allow relative motion
3. **Visual Elements**: How the robot appears in visualization tools
4. **Collision Elements**: How the robot interacts in collision detection
5. **Inertial Properties**: Mass, center of mass, and inertia tensor for dynamics

### Basic URDF Structure

```xml
<?xml version="1.0"?>
<robot name="simple_robot">
  <!-- Links define the rigid bodies -->
  <link name="base_link">
    <visual>
      <geometry>
        <cylinder length="0.6" radius="0.2"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <cylinder length="0.6" radius="0.2"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="10.0"/>
      <inertia ixx="1.0" ixy="0.0" ixz="0.0" iyy="1.0" iyz="0.0" izz="1.0"/>
    </inertial>
  </link>

  <!-- Joints connect links -->
  <joint name="base_to_wheel" type="continuous">
    <parent link="base_link"/>
    <child link="wheel_link"/>
    <origin xyz="0 0.2 -0.3" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
  </joint>

  <link name="wheel_link">
    <visual>
      <geometry>
        <cylinder length="0.1" radius="0.1"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <cylinder length="0.1" radius="0.1"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="1.0"/>
      <inertia ixx="0.01" ixy="0.0" ixz="0.0" iyy="0.01" iyz="0.0" izz="0.01"/>
    </inertial>
  </link>
</robot>
```

### Link Elements

Links represent the rigid bodies of a robot. Each link can have:

- **Visual**: How the link appears in visualization tools
- **Collision**: How the link interacts in collision detection
- **Inertial**: Physical properties for dynamics simulation

```xml
<link name="link_name">
  <!-- Visual properties -->
  <visual>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <!-- Geometry can be box, cylinder, sphere, or mesh -->
      <box size="1 1 1"/>
    </geometry>
    <material name="color_name">
      <color rgba="0.8 0.2 0.2 1.0"/>
    </material>
  </visual>

  <!-- Collision properties -->
  <collision>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <box size="1 1 1"/>
    </geometry>
  </collision>

  <!-- Inertial properties -->
  <inertial>
    <mass value="1.0"/>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <inertia ixx="0.1" ixy="0.0" ixz="0.0" iyy="0.1" iyz="0.0" izz="0.1"/>
  </inertial>
</link>
```

### Joint Elements

Joints define the connections between links and specify the allowed motion:

```xml
<joint name="joint_name" type="joint_type">
  <parent link="parent_link_name"/>
  <child link="child_link_name"/>
  <origin xyz="x y z" rpy="roll pitch yaw"/>
  <axis xyz="x y z"/>
  <limit lower="-1.57" upper="1.57" effort="10.0" velocity="1.0"/>
  <dynamics damping="0.1" friction="0.0"/>
</joint>
```

The joint types include:
- **revolute**: Rotational joint with limited range
- **continuous**: Rotational joint without limits
- **prismatic**: Linear sliding joint with limits
- **fixed**: No relative motion between links
- **floating**: 6 DOF motion
- **planar**: Motion in a plane

## XACRO: XML Macros for Robots

### Introduction to XACRO

XACRO (XML Macros) is an XML macro language that extends URDF with features like constants, properties, and macros. XACRO files use the `.xacro` extension and are processed to generate URDF files.

XACRO is particularly useful for:
- Defining constants and properties
- Creating reusable macros
- Reducing redundancy in complex robot descriptions
- Conditional inclusion of robot components

### XACRO Syntax and Features

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="robot_with_xacro">

  <!-- Define constants -->
  <xacro:property name="M_PI" value="3.1415926535897931" />
  <xacro:property name="wheel_radius" value="0.1" />
  <xacro:property name="wheel_width" value="0.05" />

  <!-- Define properties with math -->
  <xacro:property name="wheel_mass" value="${wheel_radius * 2.0}" />

  <!-- Define a macro for creating wheels -->
  <xacro:macro name="wheel" params="prefix parent xyz">
    <joint name="${prefix}_wheel_joint" type="continuous">
      <parent link="${parent}"/>
      <child link="${prefix}_wheel"/>
      <origin xyz="${xyz}" rpy="0 0 0"/>
      <axis xyz="0 1 0"/>
    </joint>

    <link name="${prefix}_wheel">
      <visual>
        <geometry>
          <cylinder radius="${wheel_radius}" length="${wheel_width}"/>
        </geometry>
      </visual>
      <collision>
        <geometry>
          <cylinder radius="${wheel_radius}" length="${wheel_width}"/>
        </geometry>
      </collision>
      <inertial>
        <mass value="${wheel_mass}"/>
        <inertia ixx="0.1" ixy="0.0" ixz="0.0" iyy="0.1" iyz="0.0" izz="0.1"/>
      </inertial>
    </link>
  </xacro:macro>

  <!-- Use the macro to create wheels -->
  <xacro:wheel prefix="front_left" parent="base_link" xyz="0.5 0.3 0"/>
  <xacro:wheel prefix="front_right" parent="base_link" xyz="0.5 -0.3 0"/>
  <xacro:wheel prefix="back_left" parent="base_link" xyz="-0.5 0.3 0"/>
  <xacro:wheel prefix="back_right" parent="base_link" xyz="-0.5 -0.3 0"/>

  <!-- Base link -->
  <link name="base_link">
    <visual>
      <geometry>
        <box size="1.0 0.8 0.2"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <box size="1.0 0.8 0.2"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="10.0"/>
      <inertia ixx="1.0" ixy="0.0" ixz="0.0" iyy="1.0" iyz="0.0" izz="1.0"/>
    </inertial>
  </link>
</robot>
```

### Advanced XACRO Features

#### Mathematical Expressions

XACRO supports mathematical expressions using Python syntax:

```xml
<xacro:property name="width" value="0.1" />
<xacro:property name="height" value="0.2" />
<xacro:property name="volume" value="${width * height * 0.05}" />
<xacro:property name="radius" value="${sqrt(2.0) * 0.1}" />
```

#### Conditional Statements

XACRO supports conditional inclusion of elements:

```xml
<xacro:property name="has_lidar" value="true" />

<xacro:if value="$(arg has_lidar)">
  <joint name="lidar_joint" type="fixed">
    <parent link="base_link"/>
    <child link="lidar_link"/>
    <origin xyz="0 0 0.2" rpy="0 0 0"/>
  </joint>
</xacro:if>
```

#### Arguments and Launch Integration

XACRO can accept arguments that can be passed from launch files:

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="robot_with_args">
  <xacro:arg name="robot_name" default="my_robot" />
  <xacro:arg name="has_camera" default="false" />

  <link name="$(arg robot_name)_base_link">
    <!-- Link definition -->
  </link>

  <xacro:if value="$(arg has_camera)">
    <!-- Camera-specific components -->
  </xacro:if>
</robot>
```

## Humanoid Robot Structure

### Humanoid Robot Kinematics

Humanoid robots have a complex kinematic structure with multiple limbs and a torso. The typical humanoid structure includes:

- **Torso**: The central body containing the main computer and power systems
- **Head**: Contains sensors (cameras, IMU) and sometimes a display
- **Arms**: Usually with 6-7 DOF each, including shoulder, elbow, and wrist joints
- **Legs**: Usually with 6-7 DOF each, including hip, knee, and ankle joints
- **Hands**: Often simplified or complex with multiple DOF

## Robot State Publishing

### Robot State Publisher

The Robot State Publisher is a ROS 2 node that reads joint position data from the `/joint_states` topic and publishes the resulting transforms to the TF (Transform) system. This allows other nodes to understand the current configuration of the robot.

```python
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
from tf2_ros import TransformBroadcaster
from geometry_msgs.msg import TransformStamped
import math

class RobotStatePublisher(Node):
    def __init__(self):
        super().__init__('robot_state_publisher')

        # Create subscriber for joint states
        self.subscription = self.create_subscription(
            JointState,
            'joint_states',
            self.joint_state_callback,
            10
        )

        # Create transform broadcaster
        self.tf_broadcaster = TransformBroadcaster(self)

        # Robot description (in practice, this would be loaded from URDF)
        self.joint_names = ['joint1', 'joint2', 'joint3']
        self.link_names = ['base_link', 'link1', 'link2', 'link3']

    def joint_state_callback(self, msg):
        """Process joint state messages and publish transforms."""
        # Create transforms for each joint
        transforms = []

        for i, joint_name in enumerate(self.joint_names):
            if joint_name in msg.name:
                # Find the joint position
                idx = msg.name.index(joint_name)
                joint_pos = msg.position[idx]

                # Create transform for this joint
                t = TransformStamped()
                t.header.stamp = self.get_clock().now().to_msg()
                t.header.frame_id = f'link_{i}'
                t.child_frame_id = f'link_{i+1}'

                # Set transform based on joint position
                t.transform.translation.x = math.cos(joint_pos) * 0.1
                t.transform.translation.y = math.sin(joint_pos) * 0.1
                t.transform.translation.z = 0.0
                t.transform.rotation.x = 0.0
                t.transform.rotation.y = 0.0
                t.transform.rotation.z = math.sin(joint_pos / 2.0)
                t.transform.rotation.w = math.cos(joint_pos / 2.0)

                transforms.append(t)

        # Publish all transforms
        self.tf_broadcaster.sendTransform(transforms)
```

### Joint State Publisher

The Joint State Publisher allows users to set joint positions through a GUI and publishes them to the `/joint_states` topic:

```xml
<!-- Launch file for joint state publisher -->
<launch>
  <node pkg="joint_state_publisher" exec="joint_state_publisher" name="joint_state_publisher">
    <param name="rate" value="50"/>
    <param name="use_gui" value="true"/>
  </node>
</launch>
```

## Validation and Tools

### URDF Validation

ROS 2 provides tools to validate URDF files:

```bash
# Check if a URDF file is valid
check_urdf /path/to/robot.urdf

# Parse and display robot information
gz sdf -p /path/to/robot.urdf
```

### Visualization Tools

Several tools help visualize and debug robot descriptions:

1. **RViz2**: ROS 2 visualization tool that can display robot models using the RobotModel plugin
2. **Gazebo**: Physics simulation environment that can load URDF files
3. **Robot Model Display**: Shows the robot structure and joint limits

### TF Tree Visualization

The TF (Transform) tree can be visualized to verify the robot structure:

```bash
# View the TF tree
ros2 run tf2_tools view_frames

# Echo transforms
ros2 run tf2_ros tf2_echo <frame1> <frame2>
```

## Best Practices

### URDF/XACRO Best Practices

1. **Use XACRO for Complex Models**: For robots with many repeated elements, XACRO macros reduce redundancy
2. **Define Constants**: Use properties for dimensions and parameters that might change
3. **Proper Inertial Properties**: Include realistic mass and inertia values for simulation
4. **Collision vs Visual**: Use simpler geometries for collision detection than for visualization
5. **Joint Limits**: Always specify appropriate joint limits to prevent damage
6. **Consistent Naming**: Use clear, consistent naming conventions for links and joints

### Humanoid-Specific Considerations

1. **Kinematic Chains**: Ensure proper parent-child relationships in kinematic chains
2. **Center of Mass**: Position the torso link to represent the robot's center of mass
3. **Balance**: Consider the robot's balance when designing the structure
4. **Accessibility**: Ensure sensors and important components are accessible
5. **Cable Management**: Plan for internal cable routing in the design

## Summary

Robot structure description using URDF and XACRO is fundamental to robotics development. These formats provide a standardized way to represent robot geometry, kinematics, and dynamics. For humanoid robots, careful attention to kinematic structure, joint limits, and inertial properties is essential for successful simulation, control, and deployment. The Robot State Publisher and related tools enable the integration of robot descriptions with the broader ROS 2 ecosystem, allowing for visualization, simulation, and control of complex robotic systems.
