# Links and Joints in Robot Description

## Introduction to Links and Joints

Links and joints form the fundamental building blocks of robot structure descriptions in ROS 2. Links represent the rigid bodies of a robot, while joints define the connections between these bodies and specify the allowed relative motion. Understanding how to properly define links and joints is crucial for creating accurate robot models that can be used for simulation, visualization, motion planning, and control.

According to Lynch and Park (2017), the kinematic structure of a robot is determined by its links and joints, which form a kinematic chain that enables the robot to manipulate objects in its environment (Lynch, K. M., & Park, F. C. (2017). *Modern Robotics: Mechanics, Planning, and Control*. Cambridge University Press).

## Links: The Rigid Bodies

### Link Definition

A link in URDF/XACRO represents a rigid body part of the robot. Each link has physical properties including:

- **Visual properties**: How the link appears in visualization tools
- **Collision properties**: How the link interacts in collision detection
- **Inertial properties**: Physical characteristics for dynamics simulation

### Basic Link Structure

```xml
<link name="link_name">
  <!-- Visual properties define how the link appears -->
  <visual>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <box size="1 1 1"/>
    </geometry>
    <material name="red">
      <color rgba="1 0 0 1"/>
    </material>
  </visual>

  <!-- Collision properties define how the link interacts -->
  <collision>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <box size="1 1 1"/>
    </geometry>
  </collision>

  <!-- Inertial properties define physical characteristics -->
  <inertial>
    <mass value="1.0"/>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <inertia ixx="0.1" ixy="0.0" ixz="0.0" iyy="0.1" iyz="0.0" izz="0.1"/>
  </inertial>
</link>
```

### Visual Properties

The visual element defines how a link appears in visualization tools like RViz and simulation environments:

#### Origin
The `origin` element specifies the position and orientation of the visual geometry relative to the link frame:

```xml
<origin xyz="0.1 0.2 0.3" rpy="0.1 0.2 0.3"/>
```
- `xyz`: Position offset (x, y, z) in meters
- `rpy`: Orientation (roll, pitch, yaw) in radians

#### Geometry
The geometry element defines the shape of the visual representation:

```xml
<!-- Box geometry -->
<geometry>
  <box size="0.5 0.3 0.1"/>
</geometry>

<!-- Cylinder geometry -->
<geometry>
  <cylinder radius="0.1" length="0.2"/>
</geometry>

<!-- Sphere geometry -->
<geometry>
  <sphere radius="0.1"/>
</geometry>

<!-- Mesh geometry -->
<geometry>
  <mesh filename="package://my_robot/meshes/link_model.dae" scale="1 1 1"/>
</geometry>
```

#### Material
The material element defines color and appearance properties:

```xml
<material name="red">
  <color rgba="1 0 0 1"/>  <!-- Red with full opacity -->
</material>

<!-- Or reference an external material -->
<material name="blue_material"/>
```

### Collision Properties

Collision elements define how the link interacts in collision detection systems:

```xml
<collision>
  <!-- Often simpler geometry than visual for performance -->
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <geometry>
    <box size="1 1 1"/>
  </geometry>
</collision>
```

Collision geometry is typically simpler than visual geometry to improve simulation performance while maintaining accurate collision detection.

### Inertial Properties

Inertial elements define the physical properties needed for dynamics simulation:

```xml
<inertial>
  <!-- Mass in kilograms -->
  <mass value="1.0"/>

  <!-- Origin of the center of mass -->
  <origin xyz="0.01 0 0" rpy="0 0 0"/>

  <!-- Inertia tensor values -->
  <inertia
    ixx="0.1" ixy="0.0" ixz="0.0"
    iyy="0.1" iyz="0.0"
    izz="0.1"/>
</inertial>
```

#### Mass and Center of Mass
- `mass`: The mass of the link in kilograms
- `origin`: The position of the center of mass relative to the link frame

#### Inertia Tensor
The inertia tensor describes how mass is distributed around the center of mass:
- `ixx`, `iyy`, `izz`: Moments of inertia around x, y, z axes
- `ixy`, `ixz`, `iyz`: Products of inertia

For common shapes, the inertia values can be calculated:
- Box: `Ixx = m*(h²+d²)/12`, `Iyy = m*(w²+d²)/12`, `Izz = m*(w²+h²)/12`
- Cylinder: `Ixx = Iyy = m*(3*r²+h²)/12`, `Izz = m*r²/2`
- Sphere: `Ixx = Iyy = Izz = 2*m*r²/5`

## Joints: Connecting the Links

### Joint Definition

Joints define the connections between links and specify the allowed relative motion:

```xml
<joint name="joint_name" type="joint_type">
  <parent link="parent_link_name"/>
  <child link="child_link_name"/>
  <origin xyz="x y z" rpy="roll pitch yaw"/>
  <axis xyz="x y z"/>
  <limit lower="-1.57" upper="1.57" effort="10.0" velocity="1.0"/>
  <dynamics damping="0.1" friction="0.0"/>
</joint>
```

### Joint Types

#### Revolute Joints
Revolute joints allow rotation around a single axis with limited range:

```xml
<joint name="elbow_joint" type="revolute">
  <parent link="upper_arm"/>
  <child link="lower_arm"/>
  <origin xyz="0 0 0.4" rpy="0 0 0"/>
  <axis xyz="0 1 0"/>  <!-- Rotation around y-axis -->
  <limit lower="-2.0" upper="1.5" effort="50.0" velocity="2.0"/>
  <dynamics damping="0.5" friction="0.1"/>
</joint>
```

#### Continuous Joints
Continuous joints allow unlimited rotation around a single axis:

```xml
<joint name="wheel_joint" type="continuous">
  <parent link="chassis"/>
  <child link="wheel"/>
  <origin xyz="0.2 0.3 -0.1" rpy="0 0 0"/>
  <axis xyz="0 1 0"/>  <!-- Wheel rotates around y-axis -->
  <dynamics damping="0.1"/>
</joint>
```

#### Prismatic Joints
Prismatic joints allow linear motion along a single axis with limited range:

```xml
<joint name="slider_joint" type="prismatic">
  <parent link="base"/>
  <child link="slider"/>
  <origin xyz="0 0 0.1" rpy="0 0 0"/>
  <axis xyz="0 0 1"/>  <!-- Motion along z-axis -->
  <limit lower="0.0" upper="0.5" effort="100.0" velocity="0.5"/>
</joint>
```

#### Fixed Joints
Fixed joints create a rigid connection with no relative motion:

```xml
<joint name="sensor_mount" type="fixed">
  <parent link="chassis"/>
  <child link="camera_link"/>
  <origin xyz="0.2 0 0.1" rpy="0 0 0"/>
</joint>
```

#### Floating and Planar Joints
These joint types allow multiple degrees of freedom but are rarely used in practice:
- **Floating**: 6 DOF motion (3 translation + 3 rotation)
- **Planar**: Motion in a plane (2 translation + 1 rotation)

### Joint Properties

#### Origin
The origin element specifies the position and orientation of the joint relative to the parent link frame:

```xml
<origin xyz="0.1 0.2 0.3" rpy="0.1 0.2 0.3"/>
```

#### Axis
The axis element specifies the joint axis in the joint frame:

```xml
<axis xyz="0 1 0"/>  <!-- Joint rotates/translates along the y-axis -->
```

#### Limits
The limit element specifies joint constraints:

```xml
<limit
  lower="-1.57"    <!-- Lower position limit (radians for revolute) -->
  upper="1.57"     <!-- Upper position limit -->
  effort="50.0"    <!-- Maximum effort (torque/force) -->
  velocity="2.0"/> <!-- Maximum velocity -->
```

#### Dynamics
The dynamics element specifies physical properties for simulation:

```xml
<dynamics
  damping="0.1"    <!-- Damping coefficient -->
  friction="0.0"/> <!-- Friction coefficient -->
```

## Kinematic Chains and Robot Topology

### Tree Structure
URDF requires that the robot model forms a tree structure with no loops. This means:
- There is exactly one path between any two links
- There is a single base link (root of the tree)
- Each link (except the base) has exactly one parent

### Example: Simple Arm Structure
```xml
<!-- Base link (root) -->
<link name="base_link"/>

<!-- Joint connecting base to first link -->
<joint name="joint_1" type="revolute">
  <parent link="base_link"/>
  <child link="link_1"/>
  <axis xyz="0 0 1"/>
  <limit lower="-3.14" upper="3.14" effort="100" velocity="1"/>
</joint>

<link name="link_1"/>

<!-- Joint connecting first to second link -->
<joint name="joint_2" type="revolute">
  <parent link="link_1"/>
  <child link="link_2"/>
  <axis xyz="0 1 0"/>
  <limit lower="-1.57" upper="1.57" effort="100" velocity="1"/>
</joint>

<link name="link_2"/>
```

### Multiple Chains
Robots can have multiple kinematic chains branching from the base:

```xml
<!-- Base link -->
<link name="torso"/>

<!-- Left arm chain -->
<joint name="left_shoulder" type="revolute">
  <parent link="torso"/>
  <child link="left_upper_arm"/>
</joint>
<link name="left_upper_arm"/>
<!-- ... more joints and links for left arm ... -->

<!-- Right arm chain -->
<joint name="right_shoulder" type="revolute">
  <parent link="torso"/>
  <child link="right_upper_arm"/>
</joint>
<link name="right_upper_arm"/>
<!-- ... more joints and links for right arm ... -->

<!-- Head -->
<joint name="neck" type="revolute">
  <parent link="torso"/>
  <child link="head"/>
</joint>
<link name="head"/>
```

## Practical Examples

### Differential Drive Robot
```xml
<?xml version="1.0"?>
<robot name="diff_drive_robot">

  <!-- Base link -->
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.5 0.3 0.15"/>
      </geometry>
    </visual>
    <collision>
      <geometry>
        <box size="0.5 0.3 0.15"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="10.0"/>
      <inertia ixx="0.4" ixy="0.0" ixz="0.0" iyy="0.8" iyz="0.0" izz="1.1"/>
    </inertial>
  </link>

  <!-- Left wheel joint -->
  <joint name="left_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="left_wheel"/>
    <origin xyz="0 0.2 -0.075" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <dynamics damping="0.1"/>
  </joint>

  <link name="left_wheel">
    <visual>
      <origin xyz="0 0 0" rpy="1.5708 0 0"/>
      <geometry>
        <cylinder radius="0.075" length="0.05"/>
      </geometry>
    </visual>
    <collision>
      <origin xyz="0 0 0" rpy="1.5708 0 0"/>
      <geometry>
        <cylinder radius="0.075" length="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="0.5"/>
      <inertia ixx="0.001" ixy="0.0" ixz="0.0" iyy="0.001" iyz="0.0" izz="0.002"/>
    </inertial>
  </link>

  <!-- Right wheel joint -->
  <joint name="right_wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="right_wheel"/>
    <origin xyz="0 -0.2 -0.075" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <dynamics damping="0.1"/>
  </joint>

  <link name="right_wheel">
    <visual>
      <origin xyz="0 0 0" rpy="1.5708 0 0"/>
      <geometry>
        <cylinder radius="0.075" length="0.05"/>
      </geometry>
    </visual>
    <collision>
      <origin xyz="0 0 0" rpy="1.5708 0 0"/>
      <geometry>
        <cylinder radius="0.075" length="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="0.5"/>
      <inertia ixx="0.001" ixy="0.0" ixz="0.0" iyy="0.001" iyz="0.0" izz="0.002"/>
    </inertial>
  </link>

</robot>
```

### 6-DOF Robotic Arm
```xml
<?xml version="1.0"?>
<robot name="six_dof_arm">

  <!-- Base link -->
  <link name="base_link">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.1"/>
      </geometry>
    </visual>
    <inertial>
      <mass value="2.0"/>
      <inertia ixx="0.01" ixy="0.0" ixz="0.0" iyy="0.01" iyz="0.0" izz="0.01"/>
    </inertial>
  </link>

  <!-- Joint 1: Base rotation -->
  <joint name="joint_1" type="revolute">
    <parent link="base_link"/>
    <child link="link_1"/>
    <origin xyz="0 0 0.05" rpy="0 0 0"/>
    <axis xyz="0 0 1"/>
    <limit lower="${-M_PI}" upper="${M_PI}" effort="100.0" velocity="2.0"/>
  </joint>

  <link name="link_1">
    <visual>
      <geometry>
        <cylinder radius="0.05" length="0.2"/>
      </geometry>
      <origin xyz="0 0 0.1" rpy="0 0 0"/>
    </visual>
    <inertial>
      <mass value="1.0"/>
      <inertia ixx="0.005" ixy="0.0" ixz="0.0" iyy="0.005" iyz="0.0" izz="0.002"/>
    </inertial>
  </link>

  <!-- Joint 2: Shoulder lift -->
  <joint name="joint_2" type="revolute">
    <parent link="link_1"/>
    <child link="link_2"/>
    <origin xyz="0 0 0.2" rpy="0 0 0"/>
    <axis xyz="0 1 0"/>
    <limit lower="${-M_PI/2}" upper="${M_PI/2}" effort="100.0" velocity="2.0"/>
  </joint>

  <link name="link_2">
    <visual>
      <geometry>
        <box size="0.05 0.05 0.3"/>
      </geometry>
      <origin xyz="0 0 0.15" rpy="0 0 0"/>
    </visual>
    <inertial>
      <mass value="1.5"/>
      <inertia ixx="0.01" ixy="0.0" ixz="0.0" iyy="0.01" iyz="0.0" izz="0.003"/>
    </inertial>
  </link>

  <!-- Additional joints and links would continue the kinematic chain -->
  <!-- Joint 3: Elbow rotation -->
  <!-- Joint 4: Wrist pitch -->
  <!-- Joint 5: Wrist rotation -->
  <!-- Joint 6: Wrist roll -->

</robot>
```

## Best Practices

### Link Design
1. **Realistic Inertial Properties**: Use actual mass and inertia values for accurate simulation
2. **Simple Collision Geometry**: Use simple shapes for collision detection to improve performance
3. **Appropriate Visual Detail**: Balance visual quality with performance requirements
4. **Consistent Units**: Use meters for distances, kilograms for mass

### Joint Design
1. **Appropriate Joint Limits**: Set realistic limits based on physical constraints
2. **Correct Axis Direction**: Ensure axis direction matches intended motion
3. **Proper Joint Types**: Use the appropriate joint type for the intended motion
4. **Realistic Effort and Velocity Limits**: Set limits based on actuator capabilities

### Common Pitfalls
1. **Zero Mass**: Never set mass to zero; use a small value instead
2. **Improper Inertia Values**: Ensure inertia values follow physical laws (positive definite matrix)
3. **Incorrect Joint Axes**: Verify joint axes produce intended motion
4. **Inconsistent Units**: Ensure all measurements use the same unit system

## Advanced Topics

### Mimic Joints
While not directly supported in URDF, mimic joints can be implemented through controllers:

```xml
<joint name="left_gripper_joint" type="prismatic">
  <parent link="gripper_base"/>
  <child link="left_gripper"/>
  <limit lower="0" upper="0.05" effort="10" velocity="0.1"/>
</joint>

<joint name="right_gripper_joint" type="prismatic">
  <parent link="gripper_base"/>
  <child link="right_gripper"/>
  <limit lower="0" upper="0.05" effort="10" velocity="0.1"/>
</joint>
```

Then use a controller to make the right gripper follow the left gripper position.

### Fixed Joint Reduction
For performance, consider combining multiple fixed links into a single link with multiple visual/collision elements:

```xml
<link name="combined_sensor_mount">
  <!-- Multiple visual elements -->
  <visual name="camera_visual">
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <box size="0.02 0.02 0.01"/>
    </geometry>
  </visual>

  <visual name="lidar_visual">
    <origin xyz="0.05 0 0" rpy="0 0 0"/>
    <geometry>
      <cylinder radius="0.02" length="0.03"/>
    </geometry>
  </visual>
</link>
```

## Summary

Links and joints are the fundamental components that define a robot's structure and kinematic properties. Links represent the rigid bodies of the robot, while joints define the connections between them and specify the allowed relative motion. Properly defining these elements is essential for creating accurate robot models that can be used for simulation, visualization, motion planning, and control. Understanding the properties and relationships of links and joints enables the creation of complex robotic systems with precise kinematic behavior.
